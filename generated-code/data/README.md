# CLEAR / sec-code-bench: подготовленные данные

Это reference-only часть эксперимента. Не монтируйте её в среду генерирующей модели.

- `clear_samples.jsonl`: 127 JSON-объектов. `source` содержит **все исходные поля** CLEAR без изменения; `prepared` — аудит и соответствия.
- `samples/CWE-N/<sample_id>`: обе исходные версии кода, исходный diff и metadata. У index 175 поле func_diff отсутствует: файл func.diff вычислен отдельно, это отмечено в diff_origin; исходная запись не дополнена и не изменена. Дополнительные `target_func_*.java` выделяют целевой метод пилота; номера строк записаны в `pilot_v1.json`.
- `sec_code_bench/mapping.json`: 37 семантически сопоставленных Java-задач, зависимости Maven, тесты, хеши доказательств и URL сервисов из тестов. `source_template` относительно исходного sec-code-bench; остальные файловые пути — относительно этой папки data.
- `sec_code_bench/templates/datasets/templates/java/...`: полные копии шаблонов. Исходные лицензии сохранены; общий Apache LICENSE находится в `sec_code_bench/LICENSE`.
- `pilot_v1.json`: 7 заданий для генерации, скрытая связь с эталонами, аудит механизма и следующий шаг адаптации. `prompt_dir`/`reference_dir` — относительно корня safe-LLM-code-generation; `target.*.path` — относительно data.
- `manifest.json`: SHA-256 источников и файлов, состав выборки, версия подготовки. Ключи `files` относительно корня safe-LLM-code-generation.
- `intersection_summary.csv`, `excluded_cwes.csv`: включённые категории и причины исключения.

Пересечение: CWE-22 (30), 79 (32), 89 (14), 94 (3), 502 (15), 611 (27), 918 (6). Итого 127 записей и 37 тестовых шаблонов. После чтения тестов JDBCInjection отмечен как related_candidate_not_confirmed_cwe89: он проверяет JDBC URL, а не SQL. Таким образом подтверждены 36 соответствий по категориям; 37-й сохранён как связанный кандидат и не рекомендуется для CWE-89. Это совпадение категорий, **не готовые 127 тестовых проектов**. CWE-200 исключён из-за отсутствия Java dynamic security-тестов в соответствующих задачах; LLM judge не считается атакой.

`requires_adaptation` означает, что атака привязана к другому интерфейсу/библиотеке. Тесты нельзя запускать на произвольной CLEAR-функции без адаптера. В частности XSLT и Groovy — разные движки, даже если оба относятся к CWE-94.

Все `dynamic_scoring_eligible` пока false: адаптеры и дифференциальная проверка не входят в эту подготовку. Для задачи 07 (CWE-918) не подтверждена и достаточность исходного фрагмента: URI validation делегирована отсутствующим helper-методам. Промпт сохранён для исследования генерации, без допуска к security-scoring.

`review_status=unreviewed_source_label_only` — запись сохранена по исходной метке, но человек не подтвердил соответствие кода CWE. В `quality.issues` отмечены обнаруженные проблемы; отсутствие записи в issues не означает отсутствие проблем. Ни func_after, ни исходные security-тесты автоматически не признаются надёжным oracle.

Аудит утечки проверяет commit, CVE, нормализованное совпадение и вхождение фрагментов в train before/after. В графе проверены доступные явные advisory/commit IDs. Его локальные числовые индексы не сопоставлялись с индексами независимых датасетов. Отсутствие совпадения не доказывает отсутствие утечки/запоминания при предобучении; provenance графа может требовать отдельного восстановления.

Проверка после переноса: `python3 scripts/validate_data.py` из корня проекта. Полная инструкция: `RUNBOOK_v1.md` в корне проекта. Для повторного построения нужны исходные CLEAR/train/граф из внешнего VCKG; для запуска генерации подготовленные ссылки на эти исходники не нужны.
